# AI内容评分与自动处理

作者要求AI创作成果有分数、流程自动处理复杂工作。当前使用共享标准库内核 `src/ncc_data/quality_core.py`，唯一量表源为 `src/ncc_data/resources/policy.json`。正文P1、纲要/场景P2、设定P3、抽取P4、修订执行P5，权重由 `quality plan` 输出，不凭记忆重写。

## 执行

1. 每份已完成AI成果独立评价。文件模式执行 `python3 scripts/ncc_state.py quality plan <范围> [章号] [--file 相对路径] --scheme P1|P2|P3|P4|P5`，正文已登记时用章号；无书准备资料用`--file`，不强制建书。派pulse的quality任务时只给评分包、成果、必要目标及可见来源，不带生成者身份或自评分。读者仍盲读，不拿量表和答案。
2. 报告外层为 `{scheme,policy_hash,content_sha256,evaluator,report}`，前三项从包继承。report字段为dimensions（每维score/evidence数组/reason）、hard、coverage、observations、summary、suggestions；分项0–5、半分步长。每维证据须可定位，高分也有依据；来源不足、维度遗漏、过期或报告不符显示待评分，不补满分。
3. `quality ingest … --scheme … --report 评审JSON`验证并计算总分。各维权重合计100，总分Σ权重×分项/5；模型提供维度与依据，程序汇总。报告存私有`.ncc/质量评分/`，不进插件仓库。
4. 默认85分达标，70–84.9按低分维度改，低于70先重构；任何维度低于3也需处理。critical/major、硬伤未通过、覆盖不足、未解析关键引用和陈旧版本优先阻断，高总分不能抵消。
5. 一个作者任务默认初稿加最多两次内容修订，机械/硬伤/品质修订共用预算；每次内容变动后复评并检查新硬伤。预算尽、往返或明显退步时保留原稿与最好候选，集中呈作者选择，不反复评分取最大值。纯传输重试保持幂等，不能用换步骤名称重置预算。
6. 关键章保留成对比较、顺序交换和记忆测试。评分分歧超10分、单维超1分或硬伤结论不同时集中复核，不直接平均过线。作者可选择较低质量分版本，用 `quality accept … --note 作者原话`留痕；不得把严重硬伤或缺证据改为通过。
7. 正文或相关规则变化，旧结论失效。标记为`origin=ai`的章节，`complete`会检查当前P1评分及硬伤/故事/作者比选条件。作者直接写作不被AI自行改回，也不因评分擅自改作者句子。

## 自动化与人介入

经理负责准备、生成、检查、返修、关联、回写和重评。作者默认只说目标、看成果/分数、采用或修改；已有明确决定不再逐步骤询问。主动暂停、编辑或改目标时固定新基线，旧任务结果只能留候选，不覆盖作者新稿。重要设定/主线偏离、无法判定的冲突、预算耗尽集中汇报并给推荐办法。

完整数据库后台通过 `ncc-data` 应用服务执行同一规则，托管采用额外要求明确对象/期限/次数及评分校准。文件模式不自动宣称有服务器托管能力。评分是本方案下的评估，作者偏好与实测读者数据独立记录；不同方案/版本不直接排名。

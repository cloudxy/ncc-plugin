# 模型、约束与事务方法

## 从不变量选择约束

先给例子与反例，再选约束归属：行内值域/必填适合行内约束；跨行唯一和引用用相应唯一/外键/排除约束及必要受控逻辑，不把查询其他行/表的规则塞进CHECK当持续一致性保证。软引用允许未迁移目标时，保留目标范围、标识、未解析状态和解析/校验流程，不能假装有硬外键。

动态本体需要类型、属性与关系定义的版本、值类型、范围与校验；稳定关系和业务读模型独立考虑。时间要明确含义、单位、区间端点和修订语义，不把故事历法强制当真实UTC。组织/任职、物品归属、知识状态等按其有效期和来源判断重叠与矛盾，不仅保存当前值。

## 事务时序

写出“读取基线→权限/范围→条件更新/新修订→事件审计→提交→投影”的原子边界。两个编辑者用同一版本时，只有符合期望版本的请求采用；影响行数为零的语义冲突应保留新稿和候选，不能读最新版本后盲目重试覆盖。

幂等标识随业务操作持久化，核对范围、操作和载荷摘要；相同标识不同载荷拒绝，重复完成请求返回原结果；幂等记录与状态提交保持一致。数据库序列化/死锁重试需要重新执行完整事务且有界，外部副作用要隔离；这不是语义版本冲突的自动放行。

## 查询快照

READ COMMITTED下不同语句可见不同提交快照；卷级导出/多页聚合要说明固定修订清单或所选事务快照如何避免混版。隔离级别按不变量选择，不能“全部SERIALIZABLE”解决所有问题，也不能只改隔离级别就取消应用版本检查。

历史/事件保留修订来源与双时间事实；当前投影可重建、可重试。既定自动定稿资格与评分/硬闸门/版本均沿受控服务，不由数据库接口或单一分数授予新权限。技术细节以[官方资料](sources.md)和实际服务端版本核对。

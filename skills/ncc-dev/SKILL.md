# NCC 开发入口

保留作者参数和当前授权，执行插件维护或升级任务。接着写章、开书、审稿、整理素材等创作请求转回对应创作技能，不引入开发质询。

先定位本技能实际路径所属 plugin_root，再从作者指定目录定位活动 Git 工作树 repo_root，显示两者、分支和版本；两者可不同，Git 操作只针对活动工作树。不得把加载技能的独立安装克隆默认当作作者项目。

读取 plugin_root 下 [开发工作流](../../docs/dev-workflow.md)：先读“定位与授权”“任务路径”；恢复任务再读“任务记录与检查接口”“恢复与证据失效”；实现、验证和交付按当前阶段读取对应标题。该文档是唯一阶段与证据规范，此入口不另定义阶段表。

查找 repo_root 下 docs/dev/tasks/ 的相关任务记录；continue/status 带任务号时读取指定记录，多任务无法消歧才询问。首次任务按规范写唯一记录和书面计划；已有决定直接继承。使用 plugin_root 下 scripts/check_dev_workflow.py，显式传 --repo 指定 repo_root，核对候选再恢复。检查器只验证确定性证据，不能代替行为评测、独立评审和作者规则确认。

只执行已授权范围；以候选、发布、克隆同步、实际加载分别汇报。外部参考无需安装；子代理遵守当次授权与可用能力。

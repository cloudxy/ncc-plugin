# 场景卡（先审故事，后写文字）

**一章 1–3 张场景卡，过了故事审才写正文。** 故事问题（这场没有翻转、选择不难、情感不对、风险没升级）在场景卡阶段发现最便宜；写成正文再改，最贵（D14）。

设计来源：麦基《故事》——每一场都让人物处境中的某个价值发生翻转，不翻转的场景就是没发生事；Swain——目标、冲突、挫折／反应、两难、决定；oh-story——细纲写"本章必须发生什么变化"，过结构验收才写正文。

## 什么时候写、谁写、谁审

- **小批量**（D16）：一次做连续几章（章数按写作模式，见 `../../ncc/references/book-layout.md` 的"词表"；`ncc_state.py scene next <书目录>` 给出下一批）。不为 50 章滚动窗做场景卡：那会过度规划，也和园丁、混合模式冲突。
- **起草**：outliner（task: scene）一次写一批，依据章纲、承诺台账、"读者此刻"、人物卡。园丁模式下章纲可以没有，outliner 从上一章结尾和人物欲望往下推。
- **故事审**：story-editor（task: story-review）一次审一批。一起审反而审得更好：风险有没有逐场升级、情绪有没有连着几章一个颜色、承诺有没有在批内推进，只有放在一起才看得出来。常规章的结论按推荐执行、记为暂定，单元复盘时作者复看；**关键章的场景卡须作者过目**。
- **登记**：`scene check <书目录> 4 5 6` 校验格式；`scene review <书目录> 4 5 6 --result pass --by story-editor` 一次记一批（有一张不合格或关键章不是作者审，整批不写入；关键章单独 `--by author`）。批内某张卡审后又改动，只需重审那一张；没过故事审的章不能标 drafting、不能组装写手包、不能 complete。

文件：`02-大纲/场景卡/ch-NNNN.md`。

## 模板

常规章（每场至少五项，三五行即可；能写出"默认写法"就加一行，写手包会提示绕开）：

```markdown
## 场景 1
- 视角：<人物>
- 目标：<他在这场要什么>
- 翻转：从「……」到「……」
- 两难：A（代价……）还是 B（代价……）
- 情感：<读者该感到什么，可用调色板：爽、燃、虐、甜、怕、笑、悲、敬、叹；压／放>
- 知识：<可选。场景里要用到专门知识时才写，如"月相；行军里程"——见下文"知识一栏">
- 素材：<可选。用得上作者的素材卡时写编号，如"M-0003、MS-0002"——见下文"素材一栏">
- 技法：<可选。用得上技法库的卡时写编号，如"T-0003"——见下文"技法一栏">
```

关键章（每场十项全写）：

```markdown
## 场景 1
- 视角：<人物>　盲区：<他此刻不知道什么（知情账）>
- 目标：……　阻碍：……
- 翻转：从「……」到「……」（人物处境里的哪个价值变了：安全↔危险、尊严↔屈辱、信任↔背叛……）
- 两难：A（代价……）还是 B（代价……）——两个都不完全对
- 情感：……（以及余味：读者合上书还剩下什么）
- 画面：全场只要一个让人记住的画面
- 风险：比上一场高在哪里
- 默认写法：<这场最容易想到的走法，写具体，如"主角亮出底牌，众人震惊"——写手会绕开它>
- 关键节拍：<这一场里要写 2–3 版的那个节拍：开场、转折、兑现或章尾>
- 本场必须发生：<来自章纲与承诺义务的事件>
```

## 知识一栏（M4，D3）

场景里写到需要专门知识的东西（夜色里的月亮、行军的里程、炼丹的火候、朝会的称谓），加一行 `- 知识：月相；行军里程`。没有就不写，不为写而写——学科不决定剧情。标了知识的章，`ncc_state.py knowledge plan` 会提示派 scholar（一批一次），scholar 写出本章知识点清单，写手包自动带上；清单不合格的章不能定稿。要用哪门知识，参考 `../../ncc/references/domains/README.md` 的场景—学科对照。

## 素材一栏（M5）

作者记下的生活素材（`../../ncc-new/references/material.md`）正好用得上时，加一行 `- 素材：M-0003`。写场景卡前先看 `ncc_state.py material list <书目录>` 的索引（一行一张，标了用没用过）。`scene check` 会查编号存在；`pack` 把素材的"内容"和"可用处"带进写手包，来源不带。不为消耗库存而挂——这场正好需要它才挂。

## 技法一栏（M9）

拆书学来的写法存在跨书技法库里（`../../ncc-deconstruct/SKILL.md` 的"学法：写技法卡"）。outliner 的派单头里会带几张和本书题材、阶段、契约相关的卡；这一场正好用得上某张卡的做法，加一行 `- 技法：T-0003`。`scene check` 会查编号存在；文笔参考类的卡，`pack` 会把它转成"写成什么"一两句带进写手包，其余类别只给规划用。单元关闭时脚本按这几章的结果给卡记好坏，卡的状态随之升降。借的是做法，不是对标书的事件——推荐理由仍先从作者种子长出来。

## 故事审清单（story-editor 用，写手看不到）

| 问 | 不通过的样子 |
|---|---|
| 这场翻转了什么？ | 场景开始和结束时，人物处境没有任何变化（文学层面的水章） |
| 两难是真的吗？ | 一个选项明显是对的；或者主角根本没得选 |
| 目标情感清楚吗？ | 写着"紧张"，但事件本身不紧张 |
| 风险升级了吗？ | 和上一场同一个量级（对治 AI"事件升级平淡"的倾向） |
| 人物的欲望和需要在场吗？ | 人物只在推动情节，看不出他自己想要什么 |
| 意料之外，情理之中？ | 读者能提前猜到走法；或者意外但没有铺垫 |
| 有没有一个画面？ | 全场只有对话和动作，没有一个能截图的瞬间 |
| 大事溯因到人了吗？（主体性） | 局势变化没有落到某个具体的人、某个具体的决定上 |
| 结构约束在场吗？（主体性） | 人物想做什么就做成什么，看不出他手里有什么牌、缺什么牌；或者反过来，只见制度不见人 |
| 主角在场吗？ | 一整章主角都不在场，或只在旁边看；主角缺席的章要有理由（如刻意切到反派视角埋信息差）——作者 novel_guide「13 规避点」：读者最想看的是主角 |
| 借了技法卡的，借的是写法吗？ | 照搬对标书的事件链，只换了人名地名；或者为了用卡硬塞进一场不需要它的戏 |
| 章尾停在哪？（看本章最后一场） | 停在事件已经完成处，读者的好奇已经满足；推荐停在变故刚发生、结果还没出来的地方（未完成的事读者记得住） |

每条不通过都给**推荐改法与理由**（guidance 问题卡格式），不只说"不行"。

## 两道水章判据

- **连载层面**：本章没有建立、推进或兑现任何读者向承诺 → `check_chapter.py` 判不过。
- **文学层面**：本章任何一场都没有价值翻转 → 故事审不通过。

两道都要过：只还账不翻转，是流水账；只翻转不还账，读者会觉得在绕圈。

# 写作简报（给写手的唯一任务说明）

**写作简报与质检清单分离。** 写手只拿简报；审稿清单、分数阈值、书魂原文一律不进写手的上下文。指标一旦写进写作提示，模型就会照着清单"做题"，交出项项达标、整体平庸的章节（古德哈特定律）。质检清单在 `../../ncc-review/references/review-domains.md`，那是审稿方的事。

简报由脚本组装（D18）：`ncc_state.py pack <书目录> <章号>` 把本章场景卡逐场转成简报，附上固定的写作提示，和读者此刻、人物声音、可用材料、前一章结尾、文风基准一起写成 `.ncc/写手包/ch-NNNN.md`。审稿文件、书魂原文、author-intent 一律不进；如果场景卡里混进了书魂原文，脚本会拒绝组装。经理可以用 `--note` 在简报末尾追加一段"特别提醒"，只写意图与材料，不写指标。"最容易想到的写法"由 outliner 写进场景卡的"默认写法"一栏。场景卡标了知识的章，写手包还带一节"本章知识点"：scholar 查过的具体写法（不带来源、不带底蕴卡），待核项附"不写具体数字和术语"。

## 简报模板

```markdown
## 第 N 章 · 场景 k 写作简报
- 视角：<人物>。他此刻不知道：<来自知情账>
- 他要：……　挡着他的：……
- 本场要翻转的：从「……」到「……」
- 他必须选：A（代价……）还是 B（代价……）。两个都不完全对。把他的选择演出来，不要替他解释，也不要让任何人说出这场的意义
- 读者该感到：<目标情感，如"先憋，后燃，留一点不安">
- 全场只要一个让人记住的画面：……
- 本场必须发生：<来自章纲与承诺义务，写成事件，如"林家当众退回聘礼"，不写承诺编号>
- 可用材料：<作者种子第 n 条；素材卡；知识台账里本场会用到的数据>
- 人物的声音：<出场人物各 1–2 句声音样例>
- 声音参照：<作者某段的节奏，只学节奏，不照抄>
- 最容易想到的写法：<经理列出 1–3 种>——不要这样写
- 这场的风险比上一场高在：……
```

关键章的关键节拍，另附一行：`本节拍写 2–3 个版本，彼此走法不同`（见 chapter-loop.md 的"发散—收敛"）。

简报末尾脚本还会附一节"篇幅"：本章字数区间（场景卡写了"字数范围：A-B"就用它，否则用项目配置），以及"分两段写、量一次、写完就停"的交付方式。字数区间是交付规格，不是质量指标。

## 十条提示原则

1. **给意图和利害，不给考核清单。** 写"读者该感到什么、人物在赌什么"，不写任何数量指标或审稿条目。
2. **给具体材料，不给形容词。** 感官细节、人物说话样例、作者种子、素材卡里的真事。"压抑的气氛"不是材料，"食堂窗口的铁盘子边沿有一圈干掉的菜汤"是。
3. **给范例，不给风格描述。** 用作者自己的一段做节奏参照，比"文笔要老练"有用得多。
4. **只写视角人物能感知到的。** 他不知道的事，叙述也不知道（知情账提供依据）。
5. **主题不说破。** 写手只拿本场的两难，不拿书魂四问；主题通过人物的选择演出来。
6. **反默认。** 经理先点出这场最容易想到的写法，写手绕开它。判断标准：意料之外，情理之中。
7. **关键处先发散，再收敛。** 关键节拍写多版，交给比选，不在写手这里自己挑。
8. **先写后删，留白。** 写完后删掉解释情绪的句子、复述前情的句子、结尾点题的句子。
9. **情绪不默认译成身体小动作。** 情绪落在选择、台词、物件和后果上，身体反应只写有后果的。依据：oh-story 的对照实验（12 篇、双盲）里，把"反应＝具体身体动作"当默认规则的那组，"指节、喉结、声音放轻"这类套路反应最多；改掉这条后身体部位提及少了约三分之二，情节点一个没丢。
10. **写完就停，不凑字数。** 写短了照实交，由作者定；为字数加的内容就是注水。

## 不进写手上下文的东西

| 不给 | 为什么 |
|---|---|
| 审稿清单、硬伤层条目、分数或阈值 | 防止照着清单做题 |
| `author-intent.md`、书魂四问原文 | 防止把主题说破；类型契约里本章需要落地的签约点，写成"本章必须发生"的事件 |
| 大纲全文、其他章正文、旧审稿报告 | 防串味、防过度规划 |
| `mind-frame.md` | 那是规划者和审稿者的判据，不是写作提示 |
| 承诺编号与台账术语 | 写成事件；回写台账是写完之后的事 |

## 故事审时就要保证的

- 每场都有翻转、两难、目标情感；关键章还有画面、风险和默认写法——场景卡格式由 `scene check` 查，内容由故事审把关。
- "默认写法"写的是具体走法（"主角亮出底牌，众人震惊"），不是空话（"避免俗套"）。
- 场景卡里提到的人物名与人物卡文件名一致，脚本才能把他们的声音样例带进写手包；提到的地名、物价等与知识台账的键一致，数据才会被带上。

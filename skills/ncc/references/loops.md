# 四个循环：章、单元、卷、书（M3-1）

长篇连载要在四种频率上看自己：每章看"写没写对"，每个单元看"读者还在不在、走向对不对"，每卷看"书魂有没有被考验、骨架要不要调"，每本书看"作者学到了什么"。章循环见 `ncc-write/SKILL.md`；本文件管后三个，以及贯穿其中的进化（文末）。

所有复盘都遵守两条：**先让数据说话**（`ncc_state.py report …` 按台账生成底稿，数据部分已填好），**再让人判断**（带「（待填）」的由对应角色与作者补写）。复盘里要作者拍板的地方，一律按 guidance 的问题卡格式给推荐与备选。

## 一、单元循环（每 10–40 章）

**开**：单元开始时 `ncc_state.py unit open <书目录> --start N --title …`，并和作者一起定本单元的关键章（系统按"卷首卷末、名场面兑现、重要人物登场与退场、主题显形"先推荐约两成，作者确认后 `chapter key`）。

**关**：单元最后一章定稿后：

1. `ncc_state.py report <书目录> unit --write` 把底稿写进 `00-策划/复盘/单元-Uk.md` 的生成区块（数据随台账刷新）；判断与决定写在区块外的"暂定决策""故事审""下一单元"各节，还有"（待填）"就关不了单元。底稿内容：本段章节（故事审是谁放行的、关键章选了哪版、情绪与钩子）、未定的暂定决策、待核知识点、承诺进出与水章、主角失去了什么、读者数据与模拟读者校准、篇幅不在区间而已收下的章（按推荐先收的请作者确认）、本段用到与从未用过的素材、记忆与交接（候选、可合并、久未出现、够格进跨书、还没落进源头的决定，见 `memory.md` 的"整理与晋升"）、场景卡引用的技法卡、本书和对标书的基线对照（只作参照）。
2. 派 story-editor（task: unit-questions）补"发展编辑的单元问题"：最打动人的是什么？主角的选择够不够难？哪个配角比主角更鲜活？哪条线该删？主角失去了什么？主题之问从哪个角度被考验？
3. 派 outliner 补"下一单元"：2–3 个候选走向（从承诺账、读者此刻、书魂推出），标推荐与理由，至少一个非主流。
4. 经理按底稿整理记忆：相近的 `memory merge`，用不上的 `memory archive`，够格的 `memory promote`；还没落进源头的作者决定写进该去的地方后 `handoff close`。
5. **呈给作者**（这是写章循环里积攒的决定集中过目的时刻）：逐条确认或推翻本单元的暂定决策与发展编辑放行的故事审；选下一单元走向；确认下一单元的关键章。作者推翻的项，按变更提议处理（格式见 `workflow/architecture.md` 的"五层决策"）。本单元记忆的变动也用白话说一句，作者要撤回的 `memory restore`。
6. `ncc_state.py unit close <书目录> --end N`（复盘文件缺"暂定决策""故事审""下一单元"任一节会被拒）。关单元时脚本自动做两件事并报出来：归档连续两个单元没再出现的记忆；结算本单元场景卡引用的技法卡（一次定稿记好，返工两轮以上或失败记差）。

园丁模式：单元复盘同时是"整理"——把本单元里长出来的伏笔、悬念、人物关系补登进三本账，补写下一单元的场景方向。

## 二、卷循环（S4 卷复盘，G4 卷间闸）

1. 本卷最后一个单元关闭后：`ncc_state.py volume end <书目录> --end N`（stage → volume）。
2. `ncc_state.py report <书目录> volume --write` 把底稿写进 `00-策划/复盘/卷N.md` 的生成区块，区块外四节须补全：
   - **承诺盘点**：开放中的承诺逐条过——该兑现的排进下一卷；拖太久的要么兑现，要么带补偿作废（`promise drop --compensation`），要么带强化延期（`promise reschedule --window A-B --note "第 X 章再露一角"`）。逾期未处置的，G4 不放行。
   - **书魂检验**：本卷从哪个角度考验了主题之问？主角的答案变了吗？书魂若还是"暂定"，第一卷卷复盘时必须定下（D7，G4 会查）。
   - **数据归因**（scout＋pulse）：追读与弃读的变化落在哪几章、对应哪类写法；模拟读者与真实数据的偏差规律，写进 reader 的校准备注（见下面的"读者数据回流与模拟读者校准"）。
   - **变更提议**：骨架（L1）要调整的条目按变更提议格式写；下一卷走向 2–3 个候选，标推荐。
   - **底蕴**（底稿自动统计）：本卷知识点按学科的条数与待核数、读者指出的出戏点；据此给一书一深学与补学清单的推荐（`domains/reading-list.md`）。
   - **进化**（底稿自动列出）：待定的进化提议与新冒出的苗头；规则级改动按下文"进化"一节走，过了锚定章回归才呈给作者。
3. story-editor 提卷级结构问题；pulse 出卷级节奏复盘（爽点密度、同型重复、同色情绪重复、弃章风险章）。
4. 呈给作者拍板，`ncc_state.py gate <书目录> volume --action pass --quote "…"`：本卷关闭，下一卷自动从下一章开始，stage 回到 serial。

## 三、书循环（完本后）

S5 收束过了 G5 之后（见 `finale.md`），做全书复盘，写入跨书**技艺库**：

- `00-策划/复盘/全书.md`：这本书哪些手法有效（附章号与读者数据）、哪些承诺读者最在意、哪里弃读最多、哪些场景卡的写法反复奏效、哪些默认写法最难绕开、模拟读者最常见的偏差。
- `{书库根目录}/_作者/技艺库/<书名>.md`：从全书复盘里提炼给**下一本书**用的条目，每条一句话＋证据＋适用条件，例如"平弧主角的信念在第二卷被亲人质疑时追读最高（第 48–60 章，追读 +12%）；适用于守护型主契约"。
- 条目模板：`ncc_state.py craft init <书目录>` 生成，书的题材、主契约、弧光、写作模式已填好；条目表每行：一句话经验｜证据｜适用条件｜标签。适用条件写具体（"守护型主契约""古代宫廷"），对所有书都成立的写"通用"。G5 会查条目表不为空。
- **跨书记忆**：收束清单列出各角色够格进跨书记忆的条目，默认晋升（`memory promote --role <角色>`），作者可以划掉；下一本书派单时按题材带上。
- 下一本书开书时（M6-4），`ncc_state.py craft read <新书目录>` 按新书的题材、主契约、弧光、写作模式挑出相关条目，写进 `00-策划/技艺库摘录.md`；经理把它们带进作者种子之后的推荐里（"源自技艺库《上一本》#3"）。有别的书的条目而没读，G0 会提醒。

## 四、读者数据回流与模拟读者校准

- **登记**：真实数据 `ncc_state.py feedback add <书目录> --ch N --source 真实 --kind 追读|弃读|划线|评论 --value … --note …`；reader 盲评的判断同样登记为 `--source 模拟`。
- **噪音隔离**：评论区原文不直接推给作者。由 reader 或运营角色汇总成信号（哪一章、多少人、什么情绪、原话摘录）再登记；作者想看原文随时可看（见 `sustain.md`）。
- **画像**（M6-2）：模拟读者按画像分别读、分别登记（`feedback add --persona`），`ncc_state.py heat` 合成弃读热力；画像定义见 `../../ncc-review/references/reader-personas.md`。
- **校准**：单元和卷复盘的底稿会把同一章的"模拟追读"（标画像）和"真实追读"并排列出。偏差规律（如"模拟读者在打斗章高估追读、在日常章低估"）按画像记成 reader 的记忆：`memory add <书目录> --role reader --kind 校准 --text "老白画像在日常章低估追读" --evidence …`；下次派该画像时 `brief --role reader --persona 老白` 把它放进派单头，作为校准备注。大模型要和真实读者对齐，只有这一条路。

## 五、进化（M11）

系统要越写越好，但不能越进化越歪：会给自己沉淀经验的智能体，很容易把一次侥幸成功的坏做法固化成套路。所以改动分四档，越难撤回、影响越大的，闸门越严。

能提议的键：

- `check.ai_level1_max`（评测＋作者确认）：A 级高危句式与一级词合计上限；插件默认 3
- `check.para_max`（评测＋作者确认）：长段告警阈值（汉字）；插件默认 200
- `check.sentence_commas_max`（评测＋作者确认）：长句告警阈值（逗号数）；插件默认 10
- `check.dialogue_run_max`（评测＋作者确认）：对白流告警阈值（段数）；插件默认 10
- `check.level1_words`（评测＋作者确认）：一级禁用词增删（+词 加，-词 删）
- `check.anachronism_words`（评测＋作者确认）：时代错置词增删（+词 加，-词 删）
- `setting.categories`（作者确认）：类目表增补（名称＋必填字段）
- `technique.kinds`（作者确认）：技法类别增补（+类别）

永不自动：铁律、公理、七律、可见范围（handoff.visibility、techniques.never、review_words）、角色身份（agents/*.md）。

**规则改动不改插件本体**：通过闸门的改动写进作者自己的覆盖层（书库根目录 `_作者/进化/覆盖.json`）。脚本读取时按"插件默认 < 作者覆盖 < 本书设置"合并，`ncc_state.py evolve rules <书库根目录>` 列出每项的生效值和来源。在多本书里都站住了的覆盖，再由开发会话收进插件本体。

**怎么走一条提议**：

1. 有证据才提：`evolve propose <书库根目录> --key … --value=… --why … --evidence "第1–20章长段告警全被作者放行"`。`evolve scan <书库根目录>` 会从各书里找苗头：多本书都新提过的同一个设定类目、多本书都被作者放行的同一个一级词。
2. 评测＋作者确认档：`evolve eval <书库根目录> EP-0001` 用改动前后的覆盖层各跑一遍锚定章（`ncc_eval.py gate`），候选让任何一章漏报或在干净章上多报就拒绝。
3. 呈给作者，确认后 `evolve apply … --quote "作者原话"`；后悔了 `evolve revert`。
4. **漏检变锚定章**：读者或作者事后发现了审稿漏掉的问题，先 `ncc_eval.py anchor new A07-短名 --suite … --era …` 建骨架，把那段原创复述成新的锚定章，再改判据。评测集随书一起长。

# 底蕴卡库（M4）

**原则（D3）：剧情在先，知识随场景来。** 学科不决定剧情；剧情走到某个场景、要用到某方面知识时，用真实学科的内容，不凭空捏造。设定可以虚构，规律不能捏造：灵气、丹药、妖兽是虚构的，但它们怎么运转，要借经济、生态、化学的真规律。

## 一、谁读卡、谁不读

| 角色 | 读什么 | 用来做什么 |
|---|---|---|
| scholar | 整张卡 | 为本章出**知识点清单**（具体的事实与写法，附来源） |
| continuity | 卡的"典型硬伤"与"诊断问句" | 硬伤层的底蕴检查 |
| outliner、story-editor | 卡的"适用场景与写法" | 写场景卡、故事审时想到"这里要用哪门知识" |
| worldbuilder | 整张卡 | 设定运转规律核对、知识台账初值 |
| **写手** | **不读卡** | 只拿 scholar 给的本章知识点（写进写手包），不拿典型硬伤、诊断问句这些审稿判据（铁律 9） |

## 二、什么时候触发（场景触发，减重版）

1. outliner 写场景卡时，场景里要用到专门知识的，加一行 `- 知识：月相；行军里程；丹炉火候`。没有就不写，不为写而写。
2. 一批场景卡过完故事审后：`ncc_state.py knowledge plan <书目录> 7 8 9` 列出哪些章要做知识点清单。**一章都没有，这一批不派 scholar。** 有的话，一批只派一次。
3. scholar（task: knowledge）按下方格式为每章写 `02-大纲/知识点/ch-NNNN.md`，并把核实过的数据写进知识台账（`fact set … --source`）。
4. `ncc_state.py knowledge check <书目录> <章号>` 校验清单格式；`pack` 会把清单带进写手包；场景卡标了"知识"而清单缺失或不合格的章，`complete` 会拒绝定稿。

## 三、本章知识点清单格式（`02-大纲/知识点/ch-NNNN.md`）

```markdown
| 知识点 | 学科 | 写成什么（给写手的具体写法） | 来源 | 状态 |
|---|---|---|---|---|
| 当天月相 | 天文 | 农历初三，傍晚西天一弯月牙，入夜不久就落 | 月相与日期对照（A09） | 已核 |
| 行军里程 | 军事 | 大队人马一日三十里，"退避三舍"的舍 | 《左传》 | 已核 |
| 丹炉火候 | 化学 | 不写温度数字，写火色由红转白、炉壁起霜 | —— | 待核 |
```

- **学科**用 24 张卡的名字（或常见简称：历史、宗教、神话、民俗、影视、人情）。
- **已核**必须有来源；**待核**的，"写成什么"一栏本身就要按宁缺律写成可感的现象，不出现具体数字（`knowledge check` 会查），写手也不会再补数字；待核项在单元复盘时交作者处理。
- "写成什么"写的是能直接进正文的具体东西，不是学科说明。知识要化进冲突、选择、代价或画面（转化律），不写成说明段。

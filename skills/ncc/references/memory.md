# 角色记忆与会话交接

经理在四个时候读本文件：回收角色的交回摘要（里面可能有记忆提议）；作者在会话里说了会影响后面工作的话；派单前组装派单头；单元整理与完本。设计与取舍见 `workflow/memory-evolution-design.md`。

## 三类经验各有一个家

- **偏好**（`pref`）：作者喜欢什么、不要什么、雷点、否决过的推荐。记忆里不另存一份；`memory add` 碰到"作者喜欢……"会拒绝并提示改用 `pref`。
- **技艺库与技法库**：作品层面什么写法成立。技艺库是完本后作者自己的经验（`craft`），技法库是拆书学来的写法卡（`technique`，见 `skills/ncc-deconstruct/SKILL.md`）。给经理推荐和规划角色用。
- **角色记忆**：这个角色干这份活容易错在哪、本书有什么约定。本文件管的就是这一类。

角色的身份与性格（`agents/<角色>.md` 的 SOUL、IDENTITY）由插件定义，不随书改写：会自己演化的"性格"正是自进化最容易歪的地方——一个越来越宽容的审稿人，每一步看起来都合理。本书特有的东西进记忆的"约定"。

## 记忆分层

| 层 | 放哪 | 进派单吗 |
|---|---|---|
| 身份 | `agents/<角色>.md` | 是（角色定义本身） |
| 本书记忆 | 书目录 `memory/<角色>.json`（源头）；`memory/<角色>.md` 是生成的视图，勿手改 | 是，只给本角色 |
| 跨书记忆 | 书库根目录 `_作者/记忆/<角色>.json`＋视图 | 是，按题材挑 |
| 历史 | `.ncc/记忆日志.jsonl`：每次新增、强化、合并、归档、晋升、撤回 | 否；`recall` 能搜到 |

种类：约定（本书特有的规矩，如"道友是平辈通称"）、教训（反复出过的问题，写成以后怎么做）、手感（作者选定或读者买账的做法）、校准（reader 画像的偏差）。

- 门槛：同类独立证据至少 2 处才生效（重复提交不计数），不到的先记为候选；约定一处即可（作者原话就是证据）。
- 相近：正文完全相同才自动合并证据；字面重合度 ≥ 0.5 的不同正文独立保存并提示候选，经理确认同义后才 merge，纠正意见用 edit 或 archive。
- 上限：本书记忆每个角色 600 字、20 条；跨书记忆每个角色 300 字。放不下的整条跳过并报告省略数，不截断句意。
- 久未出现：连续 2 个单元没再出现的（约定除外），关单元时自动归档，memory restore 可撤回。
- 晋升：有 ≥ 3 处独立证据且已生效、不是约定的，够格进跨书记忆；完本时默认晋升，作者可以划掉。
<!-- ncc:gen memory-rules 结束 -->

写手与 editor 的记忆里不许出现审稿判据词和书魂原文（铁律 9），脚本写入时就拦下。审稿反复抓到的问题，由经理在单元整理时转写成写手的"教训"——写成"怎么写"，不搬判据原文。角色之间不互相读记忆。

## 记一条

1. 每个角色交回摘要时可以附一节"记忆提议"，每条一行：`种类｜一句话｜证据`。没有就不写。
2. 经理照记：`ncc_state.py memory add <书目录> --role <角色> --kind <种类> --text "一句话" --evidence "第12章审稿 O-3"`。正文完全相同才合并独立证据；相近正文独立保存，经理判断是否同义。相反或纠正意见不能用 merge 强化旧条，改用 `edit --text` 或归档旧条。
3. 作者自己说"以后都这样"的，是"约定"，一处即可；作者说的是口味（喜欢、不要），记偏好。

## 会话交接卡

作者在会话里说的话，经理当场记下，派单时按角色切给它——子代理就是这样"继承会话"的。不全量继承：reader 看过大纲就测不出真读者会不会弃书，写手看到审稿清单就会照着做题，审稿带着生产方的讨论就会手软。

- **什么时候记**：作者说了会影响后面工作的话——一个决定、一句"这几章想写得狠一点"、一句"今天状态不好，少问我"。
- **怎么记**：`ncc_state.py handoff add <书目录> --kind 原话|决定|情绪|待办 --text "…" [--layer L0–L4|拆书] [--ch 12 或 12-15]`。原话与决定要写作用层（书魂 L0、骨架 L1、单元 L2、章 L3、文字 L4；拆书的事写"拆书"）；只管某几章的写 `--ch`。情绪与待办只给经理自己。
- **落盘时机**：上下文快满、或会话要结束时，先把还没记的作者原话补进交接卡，再继续。
- **过期与关闭**：超出 `--ch` 范围的自动不再进派单。作者的决定要落进它该去的地方（台账、场景卡、偏好、记忆），然后 `handoff close <书目录> H-0001 --to 场景卡`。交接卡是过渡，不是第二个源头；单元复盘底稿会列出还没落进源头的决定。

## 派单头与写手包

- **写手**：`pack` 组装的写手包里多两节——"本书经验（写成什么）"（写手记忆，不带编号与种类）和"作者刚说的"（切给写手的交接）；场景卡引用了文笔参考卡的，"可用材料"里多一行。读取顺序见 `context-pack.md` 的"writer 包（写手版，脚本组装的内容）"。
- **其余角色**：`ncc_state.py brief <书目录> --role <角色> [--seq 章号…] [--task 任务] [--persona 画像]`，写到 `.ncc/派单/`：本角色记忆、跨书经验、作者刚说的（按上表切）、技法参考（规划角色才有）。派单包的 inputs 里放它的路径。reader 的派单头只有该画像的校准备注；continuity、pulse 不带交接卡和技法卡。

## 整理与晋升

- **每个单元**：`report unit` 的底稿里有"记忆与交接"一节：本单元的记忆变动、候选、可合并的、久未出现的、超上限的、够格进跨书的、还没落进源头的决定。经理按底稿 `memory merge`、`memory archive`、`memory promote`；改动用白话告诉作者，作者说"撤回这条"就 `memory restore`。`unit close` 时脚本自动归档久未出现的，并结算技法卡的使用结果。
- **完本**：收束清单里列出跨书记忆候选，默认晋升（`memory promote --role <角色>`），作者可以划掉。

跨书记忆维护：`memory edit/reinforce/merge/archive/restore/consolidate <书目录> ... --shared`。例如 `memory archive <书目录> --role writer MX-0001 --shared`，会让它停止进入所有书的派单；`restore --shared` 恢复。`edit --shared --text "修正后的经验"` 保留来源和证据。操作日志记在执行命令的书中，标注 shared；原本书记忆与晋升副本分别维护，归档本书条目不会自动撤回跨书副本。跨书整理只列候选与超额项，不用某一本书的章号自动归档。reader 的两层记忆都按本次画像筛选。

## 检索

作者问"上次我们怎么定的"，先查再答：`ncc_state.py recall <书目录> 关键词… [--role 角色] [--from N --to M]`。在记忆、记忆日志、交接卡、场景卡、审稿与复盘报告、台账里做全文检索；带 `--role` 时按该角色能看的来源过滤（写手查不到审稿报告）。只用标准库，不做向量检索。

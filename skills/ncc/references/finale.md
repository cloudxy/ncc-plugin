# S5 收束（M3-2，G5 完本闸）

网文最常见的死法之一是烂尾：坑填不上、暗线散掉、结局配不上前面的铺垫。收束不是"写最后一卷"，而是一次有清单的清算。**何时进入**：作者决定开始写最后一卷（或最后一个单元）时，按 guidance 给推荐——通常在开放承诺还能在剩余篇幅内兑现完的时候，而不是写到没东西写了。

## 流程

1. `ncc_state.py finale begin <书目录>`（只能从连载阶段进入，stage → finale）。
2. `ncc_state.py report <书目录> finale --write` 把底稿写进 `00-策划/收束清单.md` 的生成区块，区块外三节须补全：
   - **承诺清算**：所有开放的读者向承诺（期权除外）逐条排进剩余章节，写明在哪章、怎么兑现；实在兑现不了的，带补偿作废，补偿要让读者觉得"交代了"。未定的暂定决策全部定下。
   - **暗线收拢**：知情账里仍有人不知道的事，逐条决定要不要在终局揭开、由谁揭开、在谁面前揭开（揭开时刻往往就是名场面）；未兑现的名场面排进剩余章节；每个核心意象安排最后一次出现，让它的含义完成最后一次变化。
   - **书魂回答**：终局给出的回答是主角答案的胜利、修正，还是胜利的代价？outliner 给 2–3 个收束方案，标推荐与理由，至少一个非主流；作者选定。
3. 收束章照常走章循环（场景卡、故事审、写作简报、硬伤审）；最后一章与名场面兑现章默认是关键章。
4. 写完后做书循环复盘（`loops.md` §三）：`00-策划/复盘/全书.md` 与 `{书库根目录}/_作者/技艺库/<书名>.md`（`ncc_state.py craft init` 生成模板，条目表至少一条）。
5. `ncc_state.py gate <书目录> finale`：检查开放承诺（期权、母题除外）与暂定决策已全部清算、书魂已确定、收束清单三节齐全、全书复盘已写、技艺库条目表不为空。作者确认后 `--action pass --quote "…"`，stage → finished。
6. 完本导出：`ncc_state.py export <书目录> --format epub`（也可 md、txt），全书合稿在 `07-导出/`。

## 收束的三个常见坑

| 坑 | 表现 | 对策 |
|---|---|---|
| 一口气清账 | 最后三章连续揭秘、连续兑现，像念清单 | 清算排进最后一卷的多个单元，每个名场面前留足欠账 |
| 书魂被说破 | 结尾让人物或叙述者总结"原来这一切的意义是……" | 书魂回答仍然只在人物的最后一次两难选择里演出来 |
| 结局太干净 | 所有人都得到了想要的 | 按"失去"线检查：主角为终局付出了什么；胜利的代价要看得见 |

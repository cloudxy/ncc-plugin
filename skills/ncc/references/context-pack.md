# 上下文包契约（context pack）

设计来源：Openwrite 的写前上下文包预检 ＋ InkOS Composer 的 protected/compressible 分层 ＋ chinese-novelist-skill 的「动笔前最后读的必须是正文语态」＋ v0.3 的"写作简报与质检清单分离"。

**无包不写。** 每章动笔前，经理组装以下内容并落档到 `04-正文/_packs/ch-XXXX.json`——它同时是写作输入、审稿对照物和事后追溯凭证。**组装前提**：本章场景卡已过故事审（`ncc_state.py scene review … --result pass`），否则 `chapter mark … drafting` 会被脚本拒绝。

## writer 包（写手版）

| 分层 | 内容 | 来源 |
|---|---|---|
| protected（必带，不压缩） | ① **写作简报**（每场一份，按 `../../ncc-write/references/writing-brief.md` 由场景卡组装）② **读者此刻**：`ncc_state.py reader-now <书目录> <章号>` 的输出 ③ 出场人物的声音样例与欲望、恐惧（人物卡与采访记录里摘，不给整张卡）④ current-focus.md | 02-大纲/场景卡、06-台账/三本账、01-设定/人物卡 |
| compressible（超预算才裁） | ⑤ 可用材料：作者种子里相关的条目、素材卡、知识台账里本章会用到的数据 ⑥ 设定词典相关条目（按本章关键词 grep）⑦ 前情摘要（前 3 章各一段） | 00-策划/作者种子.md、06-台账/知识台账.json、01-设定 |
| 锚（最后读） | ⑧ 前一章结尾 500–800 字**原文** ⑨ 文风基准.md（指纹＋基准段落＋负面清单） | 04-正文、03-文风 |

组装顺序即阅读顺序：先简报与读者，后材料与前情，**最后是正文语态**——让模型带着「上一章的声音」动笔。

**不进写手包**（写作简报与质检清单分离）：审稿清单、硬伤层条目、分数或阈值；`author-intent.md` 与书魂四问原文；`mind-frame.md`；大纲全文、其他章正文、旧审稿报告；承诺编号与台账术语（在简报里写成"本章必须发生"的事件）。开篇章需要落地的签约点，也写成事件放进简报。

## story-editor 故事审包

- 本章场景卡、上一章结尾与场景卡、出场人物卡、读者此刻、本章承诺义务、author-intent.md（书魂与契约）。
- **不给**：正文草稿、审稿报告。

## continuity / pulse 审稿包（fresh 版）

- 正文全文 ＋ 本章场景卡（核对翻转与两难是否真的写出来了）＋ 承诺义务清单 ＋ 知情台账（查视角越权）＋ 知识台账相关条目 ＋ 设定词典（仅被引条目）＋ author-intent.md 的类型契约与毒点清单（pulse 查契约用）。
- 关键章另给：各版本文件（成对比较用）。
- **不给**：写手记忆、生产讨论、旧评审报告。

## reader 盲评包

- 只有正文。开篇验收时给 1–3 章全文；关键章的记忆测试给该章全文。不给大纲、设定、场景卡、作者意图。

## 机械检查项（经理组装时先自查）

- 本章已 `chapter add` 登记；`scene check` 通过且故事审已过；承诺义务非空（本章至少建立、推进或兑现一条读者向承诺，否则就是计划中的水章）；前一章文件存在。
- 包文件写入 `_packs/` 后记入 book.json 的 `chapter.pack`，正文落盘后 sha 记入 `chapter.sha`。

## 预算

- writer 包总量建议 ≤ 12k 字（中文），超了先裁 ⑤⑥⑦，永不裁 ①–④ 与 ⑧⑨。

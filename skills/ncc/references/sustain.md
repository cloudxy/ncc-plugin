# 作者可持续（M3-7）

一本书写一到三年。多数书死于断更、写崩、心态崩，而不是不会写（公理 7）。本文件是经理照看作者的规矩。

## 一、存稿线与保更模式

- **登记发布进度**：作者每次发布后 `ncc_state.py chapter publish <书目录> --upto N`。存稿 ＝ 已定稿但还没发布的章数，`status` 会显示。
- **存稿线**：`ncc.config.yaml` 的 `buffer_min`（默认 5 章）。存稿低于存稿线时，`status` 提示进入保更模式。
- **保更模式**（经理按推荐执行，并告诉作者）：
  - 只排常规章；本单元未写的关键章往后挪，或者降为常规工序（不写多版、不做成对比较），并登记为暂定决策，单元复盘时作者复看；
  - 场景卡用常规章五项的简版；
  - 暂停二次审视、全书体检这类可以延后的工作；
  - 存稿回到存稿线以上，自动恢复。
- 作者可以随时说"不进保更模式"，经理记下原话，不再提醒到本单元结束。

## 二、倦怠信号

`status` 在近 3 章平均耗时比此前 3 章多一半以上、返工也没有减少时提示倦怠信号（耗时从标 drafting 到定稿计）。经理看到信号，不说教，给推荐与备选：

| 推荐 | 备选 |
|---|---|
| 下一单元放慢更新节奏，或插一个轻松的日常单元 | 暂时切到保更模式；跳过当前卡住的章，先写下一单元的关键章 |

## 三、噪音隔离

- 评论区、书评区的原文不直接推给作者。由 reader 或运营角色汇总成信号：哪一章、多少人、什么情绪、两三条原话摘录，登记为 `feedback add --source 真实 --kind 评论`。
- 汇总只在单元复盘和卷复盘时呈给作者；写章循环中途不打断。
- 作者想看原文随时可看——隔离是默认值，不是禁令。
- 恶意攻击、人身攻击不进汇总；只记"第 N 章有 X 条攻击性评论，未转述"。

## 四、卡文协议

作者说"卡住了"时，按顺序：

1. **先查账**：`ncc_state.py promise list <书目录> --open`、`reader-now`——多数卡文不是没灵感，而是不知道这一章该还哪笔账。给出"本章可以推进或兑现的 2–3 条承诺"，标推荐。
2. **再看场景卡**：卡在哪一项？没有翻转、两难不真、不知道读者该感到什么——对症给 2–3 个改法。
3. **过作者自有的卡文五问**：这一段有没有清晰目标？谁最想要什么？主角赢了之后会多背什么责任？冲突是人物、势力，还是只是信息堆积？爽点有没有建立足够的压力？
4. 仍然卡住：推荐跳过本章，先写下一单元的关键章，回头再补；或者对最近一个单元做二次审视（事前复盘）。

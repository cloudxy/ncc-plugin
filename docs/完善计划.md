## 一、定位重申

NCC（Novel Create Center）是**长篇网文从想法到连载的完整工作流插件**：经理窗口调度九角色，book.json 单一状态源，写-审-改分离，三道闸门。它不是写作工具合集，是一套**把创作观变成可执行判据**的系统。

成功标准（三条，作者原话派生）：
1. **写出给人看的文**——追读意愿、弃读点、划线点可测量，不是给机器看的指标文。
2. **全类型融合＋杂学底座**——八大题材可叠加，四十余门学科按通道进入而不压垮作者。
3. **选择权归作者**——机器管判据与机械检查，"有意为之"的修辞、题材方向、冻结时机由作者拍板。

## 二、理念基线：当前接受度较高的小说创作理念

### 2.1 结构层
- **三幕结构 / 英雄之旅**【文论经典】：绝大多数长篇叙事的骨架共识。
- **节拍表**【有据】：Weiland 11 节拍（Hook/激励事件/中点/高潮…）＋Bell 14 路标（镜照时刻/不归门…），author-toolkit 以此做结构 Audit（定位已有稿件节拍实际落点）。
- **黄金三章**【行业共识】：前三章定生死，30 秒入戏，第 2 章末读者能说出"这本书是关于什么"。
- **钩子链**【行业共识】：每 3–5 章一个单元钩，卷末大钩；章尾钩子强度分级（1 顺带→5 全书名场面）。
- **三级大纲**【行业共识】：总纲（主线一句话＋结局方向）→卷纲→章纲，配滚动窗（只细排未来 ~50 章）。

### 2.2 人物层
- **动机—行动—代价链**【行业共识】：每个关键行动有动机、付代价、致变化。
- **人物弧光**【文论经典】：初始状态→触发→转折→低谷→高潮→结局。
- **原型**【有据】：荣格十二人格原型＋Vogler 八叙事角色，用于陈词滥调检测与群像平衡（author-toolkit 的 Character Archetypes）。
- **人的主体性**【本会话，作者提出】："历史由人书写，历史进程由人推进"——①大事必溯因到具体人的决策；②制度通过人的处境写（《万历十五年》切片法）；③代价可见。**这是 NCC 区别于市面工作流的地基判据。**

### 2.3 文笔层
- **Show, don't tell**【文论经典】：外化而非直陈；AI 最缺的是刻意的含蓄与 obliqueness【有据，CRAFT Literary】。
- **冰山理论**【文论经典】：八分之一露出水面。
- **闲笔**【文论经典】：汪曾祺式"看似废话实则深意"——闲笔藏因果、藏时代、藏人心。
- **草蛇灰线**【文论经典】：金圣叹评点——伏笔与闲笔合法性的中文文论依据。
- **选择 vs 自动驾驶**【有据】：被骂作 AI 味的八种手法（三段式、not X but Y、冒号揭示、平行收尾…）都是合法修辞，判据是"作者选的还是模型默认的"。禁词表如"拆掉所有鼓还奇怪歌为什么无聊"。
- **三指标**【有据】：用词不可预测度（perplexity）、句长结构变化（burstiness，AI 与烂写作都窝在中等长度舒适区）、每句信息熵。

### 2.4 网文商业层
- **爽点/虐点节拍与情绪曲线**【行业共识】：情绪点分型分强度，密度按万字计。
- **代入感与规避点**【行业共识】：作者自有 novel_guide 第 12/13 章即现成判据。
- **追读/完读/弃读**【行业共识】：平台生态的核心指标，盲评读者可前置测量。
- **日更与存稿**【行业共识】：连载节奏 + batch 攒稿。

### 2.5 世界观层
- **设定为剧情服务**【行业共识】：每条设定能回答"进哪章剧情"，百科式堆料是烂尾之源。
- **量纲与规则随书**【本会话，总纲 5.0】：数值必有定义域与阈值效应；克制链/兑换率 per-book，不跨书污染。
- **伏笔台账**【行业共识＋总纲 5.0】：伏笔不登记等于不存在；due/to_plant/overdue 进每章义务清单。
- **杂学三通道**【本会话，作者提出】：四十余门学科分三通道进入——**设定硬度**（量纲/规则表管自洽）、**质感细节**（素材流管真实感，宁少勿错）、**社会洞察**（写"看似不合理却存在"的机制因果链：规矩为何存在→谁受益→谁受害→主角怎么利用或反抗）。
- **源于生活、高于生活**【文论经典＋作者要求】：正向素材采集（观察/旧闻/行业细节）＋逆向拆书对标，两头夹出真实感；"高于生活"=把生活事实模型化为戏剧结构。

## 三、工作流基线：主流接受的工作流

### 3.1 网文工业流（大众接受度最高）
选题扫榜 → 设定 → 大纲（总-卷-章）→ 黄金三章 → 日更连载 → 审校 → 发布 → 数据回流调整。NCC v0.1 的 S0–S5 主线已与此对齐。

### 3.2 AI 辅助四模式（开源社区接受度较高，均有据）

| 模式 | 代表 | 核心机制 | NCC 吸收状态 |
|---|---|---|---|
| 问答驱动 | chinese-novelist-skill | 三层递进问答、偏好记忆、单 JSON 状态机、文风锚点 | ✔ 已吸收（v0.1） |
| 管线驱动 | InkOS | 9-Agent 写审改分离、权威 JSON＋MD 投影、protected 上下文分层、双控制文档 | ✔ 已吸收（v0.1，仅思想） |
| 评审驱动 | Openwrite | 五域累加分制、SHA 复评、写前上下文包、伏笔义务清单、滚动窗 | ✔ 已吸收（v0.1） |
| 知识库驱动 | author-toolkit / haowjy | story bible＋会话日志、**只标记不代改**、风格从作者样本反推（style-creator）、按人格模拟读者（reader-sim）、角色内对话（character-sim） | ✖ **未吸收——v0.2/0.3 主缺口** |

### 3.3 平台官方参照
阅文"妙笔"垂直模型＋"妙笔通鉴"知识库（网文感参数化）【有据】——印证 NCC 设定词典＋规则表的个人版路线；番茄 AI 功能存在训练数据条款争议【有据】——外部平台不传未发布书稿。

## 六、风险与边界

1. **许可**：oh-story（自有，可直接用）、novel_guide（自有）；任何外部清单进插件前过 source-vetting 七检。
2. **判据膨胀**：craft-canon.md 控制在一屏内可读；诊断问句宁少而准，多而滥会把审稿变成表格填写。
3. **素材流反噬**：采集卡门槛过高会没人填——MVP 格式三字段（来源/场景/可用处），够用再扩。
4. **暂缓不变**（沿用 v0.1 决策）：平台化 UI/API、多人协作、规则 DSL。
